# Правила работы в этом репозитории

## Язык
- **ВСЕГДА отвечать пользователю на русском языке.** Без исключений.

## Перед любым изменением кода
- **СНАЧАЛА полностью изучи логику той части, которую трогаешь.** Прочитай функцию целиком и все связанные с ней места (кто вызывает, какие поля данных, какие соседние ветки условий), а не только тот кусок, что собираешься править.
- **Добавляя новое, можно сломать то, что уже работает.** Поэтому: убедись, что правка не задевает другие типы/ветки/роли. Существующее поведение по умолчанию должно сохраняться.
- Не угадывай имена функций и полей — проверяй их по реальному файлу (grep/Read). Если правка по `old_string` не находит совпадения — это сигнал, что ты гадаешь; остановись и перечитай реальный код.
- Не запускать фоновых агентов, которые правят `index.html`, параллельно со своими правками того же файла — это приводит к гонкам и перезаписи изменений.

## Проверка и доставка
- После правок проверять синтаксис всех инлайн-скриптов:
  `node -e "const fs=require('fs');const vm=require('vm');const h=fs.readFileSync('index.html','utf8');const m=[...h.matchAll(/<script\b[^>]*>([\s\S]*?)<\/script>/g)];let i=0;for(const s of m){i++;try{new vm.Script(s[1]);}catch(e){console.log('ERR '+i+': '+e.message);process.exit(1);}}console.log('SYNTAX_OK '+i);"`
- Коммит-сообщения — на русском, по делу.
- PR создавать только когда работа полностью готова и проверена (пользователь мёржит сразу). Если после создания PR нужны доправки — не дописывать в уже смёрженную ветку, а делать отдельный PR.

## Об устройстве проекта
- Весь фронтенд — один файл `index.html` (SPA на ванильном JS). DOM создаётся хелпером `el(tag, attrsObject, ...children)`; запросы к Supabase — через `restRequest(method, path, body, opts)`.
