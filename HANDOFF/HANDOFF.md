### Главные ограничения и обходы

**А. Supabase `/auth/v1/*` заблокирован в РФ.**
- `sb.auth.setSession()` и `sb.auth.getUser()` висят бесконечно у российских провайдеров. `/rest/v1/*` работает.
- **Обход уже в коде** — функция `loadProfileDirect()` в `index.html` (~стр. 384):
  1. Декодирует JWT из URL hash прямо в браузере (`decodeJwtPayload`).
  2. Берёт `user_id = payload.sub`, `email = payload.email`.
  3. Делает прямой fetch к `/rest/v1/profiles?id=eq.<userId>` с `Authorization: Bearer <access_token>`.
  4. Если профиля нет — создаёт через REST POST.
  5. Сохраняет сессию в localStorage в формате `sb-<projectRef>-auth-token`, чтобы `sb.from()` потом работал.
- **НЕ возвращать** прежний путь через `sb.auth.setSession`! Останется только REST-обход.
- Долгосрочно: платный Supabase ($25/мес) + свой домен для auth (`auth.zebrus.ru`).

**Б. Apple Web Push требует реальную mailto в VAPID_SUBJECT.**
- Сейчас: `VAPID_SUBJECT = mailto:xxx154xxx153@gmail.com`.
- В `push-send/index.ts` стоит автоудаление подписки при 403 от Apple.

### Telegram-бот оплат — РАБОТАЕТ В ПРОДЕ ✅

Ольга получает оплаты через `tb.ru` (платёжная страница Т-банка). Уведомления приходят в Telegram от «Помощника по оплатам». **Ручная пересылка** в `@ZebrusPayBot` → бот парсит → ищет ученика → создаёт «предложение» на сводке учителя → клик «☑ Привязать» → запись в `payments`.

**Что готово:**
- `sql/add_payment_suggestions.sql` + `add_payment_suggestions_v2.sql` — таблица с email/phone/operation_id, дедуп по operation_id.
- `supabase/functions/tg-payment-webhook/index.ts` — парсер формата `tb.ru`, матчинг по email + корню фамилии + именам из описания заказа.
- В кабинете учителя: жёлтая карточка «🤖 N новых поступлений» на Сводке + полная вкладка «💰 Оплаты» (плашки по месяцам, фильтры, ручное добавление, CSV-экспорт) + секция «💰 История оплат» в карточке ученика.
- Webhook от Telegram → Edge Function: `https://hyczawwuehrqsqqosgub.supabase.co/functions/v1/tg-payment-webhook`.

**Сложный случай:** платит мама за дочь — имя плательщика ≠ имя ученика. Парсер ищет по 3 полям параллельно (email, корень фамилии плательщика «Халиулина → Халиулин», имена с заглавной в описании заказа). Не нашёл — выпадайка со всеми учениками в модале. После подтверждения суммa улетает в `payments` с `note = order_description`.

**Почему не вебхук напрямую от Т-банка:** через Конструктор сайтов Т-банк даёт только E-mail, Telegram или amoCRM. amoCRM ~1500₽/мес — overkill для 1-2 платежей в день. amoCRM-вариант отброшен.

**Почему не Telegram→Telegram авто-пересылка:** Telegram запрещает ботам читать сообщения от других ботов (платформенное правило). Единственный способ — userbot, нарушает TOS + нужен 24/7 сервер. Для 5 жестов в день не стоит.

### UX в тренажёрах

- **Кнопка «✓ Ответить» активируется с первой буквы / первого клика** — раньше нужно было кликнуть мышью вне input, чтобы render() пересчитал состояние.
- **На iPhone клавиатура не закрывается** при наборе — фокус восстанавливается через `requestAnimationFrame`.
- **Крестик × закрытия модала тренажёра** всегда виден на мобильном — чекбокс «⚡ Мгновенная проверка» перенесён под заголовок в маленькой плашке, а не сбоку.

### Чемодан без ручки — переделан под формат ЕГЭ-тренажёра

Раньше работал на автопроверке: ученик вводит букву, поле заполняется по длине → перескок на следующее. Это **подсказывало длину ответа** (1 или 2 буквы). Сейчас:

- **Поле всегда 2 символа** — никакой подсказки длины.
- **Нет автоперехода** — после ввода ничего не происходит.
- **Кнопка «✓ Ответить»** под каждым словом: серая «Выбери ответ» → фиолетовая «✓ Ответить» (когда введена буква) → «✓ Проверено» с цветным результатом.
- **Enter** работает как клик кнопки.
- Фокус прыгает на следующее слово **только после клика** кнопки.
- `STATE.mistakeSubmitted = {}` сбрасывается при закрытии модала.

## 8. Главные UX-решения и правила

- **Достижения** — все доступны каждому, кто работает. Никаких «топ-10», «королев улья» — это стресс перед экзаменом. Категории: «За то, что ты тут», «Соревнуешься с собой», «Социальное» (учитель помечает ответ «помогло» → бейдж «🤝 Помогла другу»), финальная «👑 Прошла Краш-тест».
- **Пояснения к достижениям видны постоянно** — не во всплывашке, а на самой карточке, в ленте, в toast, в онбординге.
- **Сочинения по К1–К10, итог 22 балла** (не 21!). Жёсткое правило: К1=0 → К2 и К3 автоматом 0. Минимум 150 слов. К7–К10 ввод по числу ошибок (0→3, 1-2→2, 3-4→1, 5+→0).
- **Голосовые комментарии** в проверке сочинений: MediaRecorder → Supabase Storage, ≈ 240 КБ/мин.
- **Чат — встроенный**, не Telegram. Общий + личные диалоги.
- **Роли:**
  - Учитель — полный доступ.
  - Куратор (София, Анастасия) — видит прогресс всех, чат, «🤝 помогло», предварительная проверка сочинений. Расширенные права гибко выдаются учителем через переключатели.
  - Ученик: «свой» (постоянный) или «гость» (платит за интенсив, требует одобрения).
- **Учёт попыток в тренажёре**: кнопки «Сбросить» нет. «Проверить» → «Сохранить и закрыть» или «↻ Пройти ещё раз». Таблица `attempts`.
- **Tone of voice**: дружелюбное «ты», пчелиная тематика, эмодзи допустимы.
