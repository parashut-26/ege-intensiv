**Контекст (2026-05-12):** Ольга хочет вкладку Сочинения у учителя реорганизовать так:
- Появляется сущность «Задание сочинения» (= тема + дата выдачи + срок сдачи). Учитель её создаёт когда даёт классу написать сочинение по конкретному тексту.
- Все ответы учеников на это задание попадают **в одну группу/папку**. Без папок сейчас работа годовой давности соседствует со свежей, и легко перепутать кто к чему писал.
- Внутри группы — таблица: ученик × К1–К10 × итог. Это уже сделано как `essayCriteriaTable` в Аналитике, но без группировки по теме.
- Сортировка в Сочинениях: по дате задания (DESC) → внутри по дате сдачи.
- Связь с вариантами-пробниками: «задание сочинения» можно опционально привязать к конкретному варианту (test_variants.id) — тогда оценка автоматом подтянется в сводную варианта (вместо нынешней эвристики «ближайшее по дате»).

**Архитектура (предварительно):**
- Таблица `essay_assignments`: id, title (тема), source_text (текст сочинения), prompt (что требуется), assigned_at, due_at, variant_id (nullable), created_by
- В `essays` добавить колонку `assignment_id` (nullable, REFERENCES essay_assignments)
- Если у essay есть assignment_id — она попадает в группу. Если NULL — «свободное сочинение, без задания» (как сейчас работает «Сдать сейчас»).

**Why:** У Ольги в Excel сейчас именно так — каждый тест/пробник содержит сочинение, и сводная строится «по варианту» с колонками К1–К10. Без группировки в платформе быстро потеряется кто к чему писал, особенно когда у неё одновременно идут несколько групп.

**How to apply:** После интенсива (4 июня). Связано с задачей решалки вариантов (todo_variants_solver_v2) — там тоже будет «задание». Можно делать вместе: одна сущность «assignment» которая бывает test-type или essay-type.
