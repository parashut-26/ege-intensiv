**Контекст 2026-05-19:** Сейчас теория задания хранится в одном поле `ege_tasks.theory_md` (markdown). Редактор показывает большой textarea + панель форматирования + live preview. Вставка фото работает (через `<img>` в текстовом потоке), но Ольга по аналогии с «Разогревом» / «Постами для дней» (вкладка где блоки text/image/link отлично смотрятся) хочет такой же блочный формат для теории заданий.

**Что есть:** в платформе уже работает конструктор блоков в `warmup_blocks` (типы: text, game, link, image, poll) — отдельная таблица с `day_id`, `ord`, `type`, `title`, `body`, `url`, `image_url`, `image_urls`, `config`, `is_published`. Учитель редактирует через UI «🔥 Разогрев» и «🔥 Посты по дням интенсива», ученик видит как красивые карточки в overlay.

## Что хочется

1. **Новая таблица** `task_theory_blocks` (или расширить `warmup_blocks` поддержкой `task_n` вместо `day_id`):
   - `task_n` (1-26)
   - `ord` — порядок
   - `type` (text / image / link / game / video / poll)
   - `title`, `body`, `url`, `image_url`, `image_urls`, `config`
   - `is_published` (учитель может черновить блок, не показывая ученику)

2. **UI редактирования теории** — переделать модал «✏️ Редактирование задания N» так, чтобы вместо одного textarea был **список блоков** с возможностью:
   - + добавить блок (выпадайка: 📝 текст / 📷 фото / 🔗 ссылка / 🎮 игра / 🎥 видео)
   - перетаскивать блоки (drag-handle) для изменения порядка
   - удалять блок
   - редактировать содержимое

3. **В блоке `text`** — полная панель форматирования (как сейчас в редакторе теории): **Ж К П**, цветные маркеры, заголовки H1/H2, маркированный/нумерованный списки, ссылка, горизонтальная линия. Плюс live preview под этим блоком.

4. **В блоке `image`** — кнопка загрузки + изображение с подписью.

5. **В блоке `link`** — карточка-превью с заголовком, описанием, URL (можно простой <a> или с автогенерацией preview по OG-метатегам).

6. **В блоке `game`** — выбор существующей игры из `/games/<slug>/`.

7. **У ученика** — теория задания рендерится как **последовательность карточек** разных типов (точно как «Разогрев» / посты в днях интенсива). Markdown → HTML рендер через marked внутри text-блоков.

8. **Миграция данных:** существующий `ege_tasks.theory_md` нужно автоматически конвертировать в один text-блок при первом открытии. Учитель потом сможет разбить его на несколько блоков и добавить картинки.

## Why

- Markdown с inline `<img>` тегами работает, но Ольге **визуально сложно** редактировать длинный текст с картинками посередине.
- В «Разогреве» она уже привыкла к блочному конструктору — единообразие интерфейса упрощает работу.
- Блочный формат **легче расширять**: завтра захочется добавить «карточку с цитатой», «карточку с тестом-самопроверкой» — в блочной модели это новый тип, в markdown — переписывать рендер.
