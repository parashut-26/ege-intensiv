**Контекст 2026-05-16:** Закончится интенсив «Краш-тест 2026» 4 июня. Через 2 недели (≈18 июня) старт **летнего курса** для 11 класса (6 недель). После лета — **годовой курс** для классов 6, 7, 8, 9, 10, 11.

**Принципиальное решение:** платформа переезжает с модели «одна школа на один интенсив» к модели **много курсов**. Ученики могут состоять в нескольких курсах одновременно, видят только активные, учитель видит все включая архивы.

## Концептуальная модель

Новые сущности (в порядке важности):

1. **`courses`** — курс. Поля: id, title, grade (6-11, NULL для интенсива), starts_at, ends_at, is_archived, created_at.
2. **`enrollments`** — ученик ↔ курс. Связь many-to-many.
3. **`topics`** — темы. Привязаны к курсу. Например, «Орфоэпия», «Сложное предложение».
4. **`course_days`** — день курса. Поля: course_id, date, unlocks_at (для поэтапного открытия), title, theme_id.
5. **`day_blocks`** — блоки внутри дня (карточка теории / видео / викторина / mini-essay). Поля: day_id, kind (theory|video|quiz|essay), order, content (JSONB), task_n (если задание ЕГЭ).
6. **`day_progress`** — прогресс ученика по дню. status (locked|open|in_progress|done).
7. **`block_responses`** — ответ ученика на конкретный блок (привязка к попытке/сочинению).

## Решения Ольги (зафиксировано 2026-05-16)

- **Поэтапность:** «замок» на следующих днях, пока вчерашний не закончен. НЕ открывать вперёд. Если ученик пропустил неделю — догоняет всё разом. Мотивирует не бросать.
- **AI-отчёт родителям:** **каждое воскресенье вечером**, автоматически (не пятница — на выходных у учеников ещё есть время сдать недельный пятничный тест). Cron-задача. Учитель в субботу-воскресенье может прочитать и поправить перед публикацией.
- **Свободный ответ (mini-essay) без эталона:** **AI предварительно + куратор утверждает**. AI даёт первичные пометки (стиль, грамматика), куратор смотрит и подтверждает или дорабатывает. Аналогично существующему сценарию с проверкой сочинений по К1-К10.

## Фаза 1 — до 18 июня (срочно, 2 недели после интенсива)

Минимум для разделения интенсива и летнего курса:

1. Сущность `courses` + `enrollments` в БД.
2. Все текущие данные интенсива получают `course_id = 'krashtest-2026'`.
3. Интенсив `is_archived = true` после 4 июня.
4. Переключатель курсов сверху в кабинете учителя.
5. Кабинет ученика — видны только активные курсы (RLS по enrollments).
6. Создать «Летний курс 2026 · 11 класс» — пустой каркас.
7. Зачислить летних учеников (массовый импорт через существующий import-students).

Этого достаточно, чтобы летние не видели интенсив, а интенсивные не видели лето. Контент летнего курса заполняем по мере хода (как сейчас с интенсивом).

## Фаза 2 — лето (июль-август), 2-2.5 месяца

Полноценный годовой курс:

1. `topics` + UI редактора тем (учитель создаёт темы, привязывает к классу).
2. `course_days` + календарный вид у учителя (заполнить весь сентябрь-май одного класса заранее или итерационно).
3. `day_blocks` 4 типа:
   - **theory** — карточка теории (картинка + текст, как сейчас «Теория» по 26 заданиям, но шире).
   - **video** — встраивание YouTube/VK Video или прямая загрузка в Supabase Storage.
   - **quiz** — викторина (реюз QUIZ_BANK + новые форматы).
   - **essay** — свободный ответ с эталоном или без.
4. `day_progress` + механика «замка» на UI.
5. Edge Function `weekly-report` + YandexGPT (промт собирает ошибки по темам за неделю).
6. **Родительский кабинет** (см. `project_intensive_platform.md`) — нужен здесь, родители видят AI-отчёт.
7. Деление учеников годового на 6 классов (поле `grade` в `courses`).
8. Cron «воскресенье 20:00» для AI-отчётов.

## Why

Ольга ведёт три типа продукта параллельно: краш-тест (срочные интенсивы), летние курсы, годовой курс с ежедневной нагрузкой. Без разделения на курсы — каша. Без поэтапности и тем — невозможна автоматическая аналитика (которую сейчас даёт Notion + AI). С платформой = всё в одном месте, нет переписывания ошибок руками.
