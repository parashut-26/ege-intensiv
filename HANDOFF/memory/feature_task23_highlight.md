**2026-05-20:** Ученица прислала фидбек: «во 2 задании неудобно, слова не выделены, которые нужно по смыслу соотнести». Реализовала подсветку + UI для ручной правки.

## Что добавлено

### 1) Глобальные утилиты подсветки
В верхнем уровне файла (рядом с `parseTheoryMeta`, вокруг строки 1145) лежит 5 функций — видны и из тренажёра, и из questionPreview:
- `renderInlineMdGlobal(text)` — `**слово**` → `<strong>`, HTML escape
- `highlightCapsGlobal(html)` — слова CAPS на 2+ буквы → жёлтый фон (наследие задания 5/паронимы)
- `rootOfCapsGlobal(word)` — корень CAPS-слова (`ЭПИГРАФ`→`эпигра`, `МАССА`→`масс`)
- `extractTargetCapsWordsGlobal(text)` — из формулировки `1) ЭПИГРАФ. … 2) МАССА. …` достать CAPS-слова
- `highlightRootsInTextGlobal(html, capsWords)` — обернуть корни в `<mark>` с жирным + подчёркиванием + жёлтым фоном
- `formatNumberedOptionsGlobal(text)` — разнести варианты «1) … 2) …» по строкам с жёлтой полоской слева

### 2) Приоритет ручной разметки
`highlightRootsInTextGlobal` сначала проверяет `<strong>` в тексте (от `**слово**` в md). Если есть — подсвечиваем **только их**, корневую эвристику НЕ применяем. Если нет — fallback на корни (для старых вопросов без разметки).

Это решает кейс «ПРОСТОТА vs ПРОСТАЯ» — одинаковый корень `прост`, эвристика подсвечивала всё подряд. Теперь Ольга оборачивает в `**слово**` именно нужное и подсвечивается ровно оно.

### 3) Редактор sourceText в банке (modalQuickEditQuestion ~ строка 4361)
Раньше через UI sourceText вообще нельзя было править — только через прямую правку JSON в БД. Сейчас добавлено:
- **textarea** для `q.sourceText` (показывается если у вопроса есть sourceText)
- **кнопка «🟡 Ж — обернуть выделенное в \*\*жирное\*\*»** — выделил мышкой слово → нажал → оборачивается в `**...**`
- **live-превью** под textarea — Ольга сразу видит, как ученик это увидит, с подсветкой по корням или по `**...**`
- При сохранении `q.sourceText` обновляется в QUIZ_BANK + БД

### 4) Тренажёр + превью банка
- В тренажёре ученика (`bank.forEach((q, i) =>` вокруг строки 9418): для `taskN === 2 || taskN === 3` если формулировка содержит `\d+\)\s+[А-ЯЁ]{3,}` → разносим варианты + подсвечиваем корни в sourceText.
- В превью банка учителя (`questionPreview` ~ строка 16436): тот же formatNumberedOptions + highlightRootsInText. Ольга видит то же, что ученик.

## Why
ОБЗ ФИПИ-2026 импортировался **без жирного форматирования** ключевых слов. В нативном PDF слова жирные, но через парсер docx → JSON это потерялось. Текущее решение даёт два пути: (а) автоподсветка по корню для быстрого старта; (б) ручная правка через `**слово**` для точности.

## How to apply
- При добавлении нового задания в банк сразу спросить Ольгу, в каком формате он есть в исходнике (с жирным или без), и при импорте парсить bold-теги в `**...**`.
- Если будет жалоба «не туда подсвечивается» — это всегда конкретный вопрос, путь решения один: открыть в редакторе банка → выделить нужное слово в sourceText → нажать 🟡 Ж → сохранить.
- Похожая логика подсветки понадобится для задания 1 (логико-смысловые отношения — нужно подсветить место пропуска `<…>`) и задания 23-26 (анализ языковых средств — подсветить термины-указатели). Когда дойдут руки — переиспользуй `highlightRootsInTextGlobal` или сделай аналогичную.

См. также `feedback_git_lock.md` про recovery после `find -delete` — то же утро.
